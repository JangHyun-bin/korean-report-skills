# 한국어 보고 문서 문체

기술·사업 문서의 한국어 서술 규약. 시각 디자인 규약(색·타이포·도해)과 제작 절차는
`korean-report-doc` 스킬이 담당하며(`references/design.md`), 이 스킬의 범위는
**문장과 프레이밍**에 한정한다.

원칙 하나로 요약하면 이렇다. **문서는 말이 아니라 기록이다.** 말할 때 자연스러운 표현이
문서에서는 대개 어긋난다.

예시는 가상 사례 「A사 — 인라인 계측 체계 확립과 수율 개선」에서 가져왔다.
도메인은 예시일 뿐이고 규칙 자체는 분야를 가리지 않는다.

---

## 1. 문체

### 1.1 제목은 명사구

서술형 제목은 논평처럼 읽히고 문서 개정 시 낡는다. 제목은 주제를 지시하고, 주장은 본문이 한다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 일정이 말하는 것 | 일정 시사점 |
| 필터는 제 역할을 하였다 | 검출 필터의 정상 동작 |
| CD는 같은 웨이퍼 안에서도 흔들린다 | 웨이퍼 내 CD 편차 |
| 4번이 기술적으로 가장 중요하다 | 4번의 기술적 우선순위 |
| 현재 시스템은 편차 문제를 덮고 있다 | 증상 억제의 구조와 그 대가 |

한정이 필요하면 줄표를 쓴다 — `오버레이 — 핵심이자 약점`, `상한 2.5 nm와 고객 규격의 여유`.

**예외**: 도해(SVG) 안의 제목은 그림이 말하는 주장이므로 문장이어도 된다.

### 1.2 구어체 환언 금지

기술적 사실을 일상어로 바꾸면 그 사실이 곁말처럼 읽힌다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 검사 장비가 보는 전부 | 검사 장비의 검출 범위 |
| 모델이 내는 것 | 모델의 출력 |
| 크기를 재는 것이 싸다 | 크기를 재는 편이 비용이 낮다 |
| 반토막이 된다 | 절반 수준으로 낮아진다 |
| 25%가 흔들린다 | 25%의 편차가 있다 |
| 레시피를 외운 것이 된다 | 레시피에 과적합한 결과에 가깝다 |
| 기준 웨이퍼에 갇혀 | 기준 웨이퍼에 고정되어 |
| 틀린 검출을 거르는 법 | 오검출의 기각 |
| 손도 대지 못한다 | 관여하지 않는다 |
| 기반을 다진다 | 기반을 확립한다 |
| 하는 일 (표 항목) | 역할 |

### 1.3 의인화·물리 은유 금지

주어가 사람이나 사물이 아니면 동사도 그것의 것이 아니어야 한다.
분야 표준 비유라도 서술 문체와 충돌한다.

**판정법 — 주어를 사람이나 물건으로 바꿔 본다.** 그 자리에서 자연스러우면 전용된 비유다.

- `로트가 흐른다` → "물이 흐른다"의 전용 → 물리 은유
- `문서가 다룬다` → "사람이 사안을 다룬다"의 전용 → 약한 의인화
- `다이가 죽는다` → "사람이 죽는다"의 전용 → 의인화

| 쓰지 않는다 | 쓴다 |
|---|---|
| 다이가 죽는다 | 다이가 불량으로 판정된다 |
| 양품이 살아남는다 | 양품이 잔존한다 |
| 결함이 웨이퍼를 갉아먹는다 | 결함이 수율을 저하시킨다 |
| 파티클이 앉는다 | 파티클이 부착된다 |
| 챔버가 늙었다 | 챔버가 노후화되었다 |
| 한 로트가 분산을 독점한다 | 한 로트가 분산의 대부분을 차지한다 |
| 로트가 흐른다 | 로트가 공정을 통과한다 |
| 본 문서는 …를 다룬다 | 본 문서는 …로 한정한다 · …를 정의한다 |
| 세션이 살아 있다 | 세션이 유지된다 |
| 큐가 밀린다 | 큐에 적체가 발생한다 |
| 값이 튄다 | 값에 이상치가 발생한다 |

**단, 용어는 원형을 유지한다.** `킬러 디펙트` · `뉴슨스` · `드리프트` · `빈닝`은 비유가 아니라
이름이며, 번역하면 정밀도가 떨어진다. 판정법을 적용하기 전에 그 말이
**개념의 이름인지 서술인지**를 먼저 가른다.

그래서 다음 한 줄이 두 규칙의 경계를 보여준다 — **이름은 남기고 서술만 바꾼다.**

| 킬러 디펙트가 다이를 죽인다 | 킬러 디펙트가 다이 불량을 유발한다 |
|---|---|

### 1.4 어미는 문어체

| 쓰지 않는다 | 쓴다 |
|---|---|
| 됐다 · 됐고 · 됐으며 | 되었다 · 되었고 · 되었으며 |
| 했다 · 했고 · 했으나 | 하였다 · 하였고 · 하였으나 |

도해 라벨과 표 셀에도 동일하게 적용한다.

전역 치환으로 처리하되 **인용문과 코드 블록은 제외한다.** 남의 말을 옮긴 자리까지
문어체로 바꾸면 인용이 아니게 된다.

**한 문서에서 평서체와 합니다체를 섞지 않는다.** 둘은 독자와의 거리가 다르므로
혼용하면 문서가 초안처럼 읽힌다. 문서 본문은 평서체로 쓰고, 송부 메일·요청문은 합니다체로 분리한다.

| 구분 | 어미 | 용도 |
|---|---|---|
| 평서체 | `~한다` · `~이다` | 기술보고 · 정의서 · 연구노트 · 진행현황 |
| 합니다체 | `~합니다` · `~입니다` | 송부 메일 · 협의 요청문 · 대외 안내 |

> ✗ 검사 레시피가 확정됐습니다. 로트가 들어오면 빈닝이 돌아간다.
> ✓ 검사 레시피를 확정하였다. 로트가 투입되면 빈닝이 수행된다.

한 문서 안에 두 체가 필요하면 **문서와 커버레터를 분리**한다.

### 1.5 번역투 제거

| 쓰지 않는다 | 쓴다 |
|---|---|
| 각 절은 근거를 함께 갖는다 | 각 절에 근거를 명시하였다 |
| 모든 사슬이 승인 하나에 걸려 있다 | 승인 이후 착수할 수 있다 |
| 계측 축은 수치를 냈다 | 계측 체계는 수치를 확보하였다 |
| 양산 적용 창 | 양산 적용 가용 기간 |
| ~를 성립시키는 사슬 | 준비 단계의 선행 관계 |

### 1.6 문서의 자기 설명 배제

초록 자리에 사용법이 들어가면 정보가 밀려난다.

> ✗ 본 문서는 무엇을 넣을지 정하기 위한 내부 검토 자료다. 각 절은 후보와 그 근거,
>   그리고 그 자리에서 받아야 할 결정을 함께 담는다.
>
> ✓ 분기 품질보고를 3주 앞두고 현재 상태를 정리한다.

절 제목이 「요약」이면 성격은 이미 전달된다. 구성 안내가 정말 필요하면 한 문장으로 줄인다.

### 1.7 과장·위협 표현 금지

소요와 위험은 사실로 적고, 압박으로 적지 않는다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 하루면 끝난다 | (삭제하거나) 선행조건 |
| 이번 분기에 시작하지 않으면 양산 일정이 위험하다 | 착수 시점 확정 필요 |
| 웨이퍼 한 장이면 30분 | (삭제) |
| 착수가 늦어질수록 회복이 어려워진다 | 착수 시점을 먼저 확정한다 |
| 양산 검증이 유일한 답 | 양산 조건 검증이 필요하다 |

### 1.8 어휘 선택 — 정밀도 기준

**쉬운 말이 기준이 아니라 정밀도가 기준이다.** 한자어와 영문은 격식을 위해서가 아니라
의미역을 좁히기 위해 쓴다. 정밀도가 향상되지 않으면 쓰지 않는다.

#### 광의 고유어를 협의 한자어로

고유어 동사는 의미역이 넓어 계약·규격 문서에서 해석이 분기한다.

**판정법 — 그 동사에 목적어를 바꿔 끼워 본다.** 서로 다른 종류의 목적어가 모두 자연스러우면
의미역이 넓은 것이므로 협의어로 대체한다.

- `넘긴다` → 데이터를 / 업무를 / 권한을 넘긴다 → 전부 성립 → **전달 · 이관 · 위임**으로 분리
- `늘다` → 정밀도가 / 비용이 / 기간이 늘다 → 전부 성립 → **향상 · 증가 · 연장**으로 분리
- `갈린다` → 해석이 / 승패가 / 길이 갈린다 → 전부 성립 → **분기 · 결정 · 분리**로 분리

아래 표는 **자주 나타나는 예시이며 목록이 아니다.** 표에 없는 동사도 판정법으로 검사한다.

| 광의 | 협의 | 갈라지는 의미 |
|---|---|---|
| 다룬다 | 한정한다 · 규정한다 · 정의한다 | 범위 획정인지 정의인지 |
| 나눈다 | 구분한다 · 분류한다 · 배분한다 | 경계인지 유형인지 몫인지 |
| 맞춘다 | 정합한다 · 정렬한다 · 보정한다 | 논리인지 위치인지 값인지 |
| 바꾼다 | 변환한다 · 대체한다 · 개정한다 | 형식인지 대상인지 문서인지 |
| 넘긴다 | 전달한다 · 이관한다 · 위임한다 | 데이터인지 업무인지 권한인지 |
| 지운다 | 삭제한다 · 제거한다 · 소거한다 | 항목인지 요소인지 값인지 |
| 늦춘다 | 순연한다 · 유예한다 | 일정인지 의무인지 |
| 적는다 · 적었다 | 명시한다 · 기재한다 · 기록한다 | 규정인지 항목 입력인지 이력인지 |
| 나온다 · 나와야 | 도출된다 · 산출된다 · 확정된다 | 결과인지 계산인지 승인인지 |
| 넣는다 | 포함한다 · 등재한다 · 삽입한다 | 범위인지 목록인지 위치인지 |
| 뺀다 | 제외한다 · 차감한다 | 범위인지 수량인지 |
| 붙인다 | 부착한다 · 부기한다 · 첨부한다 | 표기인지 주석인지 파일인지 |
| 만든다 | 생성한다 · 작성한다 · 구축한다 | 데이터인지 문서인지 환경인지 |
| 고친다 | 수정한다 · 보완한다 · 개정한다 | 오류인지 미비인지 문서인지 |
| 잡는다 | 검출한다 · 산정한다 · 고정한다 | 이상인지 수치인지 값인지 |
| 둔다 · 두면 | 배치한다 · 유지한다 · 설정한다 | 위치인지 상태인지 값인지 |
| 긋는다 | 획정한다 · 구획한다 | 범위인지 구역인지 |
| 막는다 | 차단한다 · 방지한다 | 경로인지 사태인지 |
| 는다 · 늘어난다 | 향상된다 · 증가한다 · 연장된다 | 품질인지 수량인지 기간인지 |
| 갈린다 | 분기한다 · 분리된다 | 해석인지 대상인지 |
| 올라간다 · 내려간다 | 상승한다 · 하락한다 | (수치는 상승·하락, 위치는 이동) |
| 생긴다 | 발생한다 · 형성된다 | 사태인지 구조인지 |

**교정안도 이 표를 통과해야 한다.** 다른 절에서 제시한 「쓴다」 쪽 문장에
광의 고유어가 남아 있으면 규칙이 자기모순이 된다.

> `이관`과 `전달`을 함께 「넘긴다」로 적으면 책임 범위가 무너진다.
> 업무분장 문서에서 「이관」과 「추가 수행」의 구분이 쟁점이 되는 일이 실제로 있다.

#### 표기 층위

| 층위 | 표기 | 예 |
|---|---|---|
| 식별자 · API · enum | **영문 원문 그대로** | `waferId` · `InspectionStarted` · `SUCCESS` · `retryLimit 3` |
| 기술 개념 | 영문 또는 정착 번역 | `payload` · `endpoint` / 좌표계 · 정합 · 계측 |
| 행위 · 관계 서술 | 한자어 | 한정한다 · 이관한다 · 순연한다 · 산정한다 |

**enum 값과 필드명은 번역하지 않는다.** `SUCCESS`를 「성공」으로 적으면 코드와 문서가 어긋난다.
**규격·API에 등장하는 말은 한글 음차보다 영문 표기**를 쓴다. 원어와 1:1로 대응해야 검색·대조가 된다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 세션 키 · 페이로드 | `session key` · `payload` |
| 엔드포인트 · 콜백 | `endpoint` · `callback` |

**단, 분야에 정착한 개념어는 한글 음차를 유지한다.** `드리프트` · `뉴슨스` · `빈닝`은
규격상의 이름이 아니므로 영문으로 되돌리면 읽기 비용만 증가한다. 판정 기준은
**코드·API 문서에 같은 철자로 존재하는가**이다.

#### 정밀도 없는 격식체는 제거

| 쓰지 않는다 | 쓴다 |
|---|---|
| 상기 · 하기 · 여히 | 위 · 아래 · 다음과 같이 |
| 익일 · 명기 · 요망 | 다음 날 · 명시 · (동사로) 요청한다 |
| 스캐폴드 | 구성안 |
| 공정 정본 | 공정 기준 문서 |
| 풋프린트 | 점유 면적 |

**한 문장에 영문과 한자어를 겹쳐 쌓지 않는다.** 밀도가 아니라 탁도가 상승한다.

> ✗ 검사 endpoint의 payload를 canonical ID로 정합 후 전달 요망
> ✓ 검사 endpoint의 payload를 표준 ID 기준으로 정합한 뒤 전달한다

조직 내부에서 굳어진 용어는 그대로 두되, 외부 문서에서는 처음 나올 때 한 번 풀어 쓴다.

## 2. 프레이밍

### 2.1 결함 서사를 역량 서사로

같은 사실이라도 주어가 '결함'이면 문서 전체가 사고 보고서가 된다.
주어를 '측정 역량'으로 옮기면 사실을 지우지 않으면서 성격이 바뀐다.

> ✗ 2.2 계측이 드러낸 결함 넷
> ✓ 2.2 구조적 개선 — 인라인 계측 체계 확립과 수율 향상

| 쓰지 않는다 | 쓴다 |
|---|---|
| 검출 결함의 71%가 뉴슨스로 버려지고 있었다 | 검사–빈닝 기준 연결 — 검출률과 계측 시간을 동시에 개선 |
| 수율 벤치가 양산 조건으로 측정되지 않았다 | 양산 조건 기준 수율 벤치 확립 |
| 인라인 계측이 수율 분석에 못 들어갔다 | 인라인 데이터의 수율 분석 체인 편입 |
| 장비 매칭 검증이 사흘간 중단되었다 | 장비 매칭 검증 경로 복구 |
| 세 공정이 합쳐서 실패하였다 | 세 공정이 서로의 계측 기준을 참조하지 않는 구조였다 |
| 추가 계측 필요(오버레이 미달) | 오버레이 계측 보강 대상 |

### 2.2 결과 우선 구조

각 항목은 **수치로 시작**하고 배경은 후행 배치한다. 배경이 선행하면 문제 서술이 되고,
결과가 선행하면 성과 서술이 된다.

```
#### ① 검사–빈닝 기준 연결 — 검출률과 계측 시간을 동시에 개선
📊 결과 · 유효 검출률 4/7 → 5/7 · 웨이퍼당 계측 ~900 → ~590초

(그 다음에 배경과 원인)
```

### 2.3 리스크는 대응과 함께

리스크만 나열하면 문제 제기가 되고, 대응을 병기하면 관리 중이라는 서술이 된다.
대응을 기재할 수 없으면 그 항목은 외부 문서에서 제외한다.

### 2.4 상대의 요청을 기점으로

협의 문서가 우리 이야기로 시작하면 통보가 된다. 상대의 요청·질문을 먼저 두고
그에 대한 응답으로 구성한다. 고객사에 보내는 품질 보고라면 고객이 제기한 항목이
먼저 오고 우리 분석이 뒤에 온다. 단, **요청자를 명시하는 것이 부담이 되는 경우**에는
「아젠다」처럼 중립 표제로 두고 내용만 남긴다.

### 2.5 한계의 선제 제시

"정해 주십시오"는 상대에게 판단 근거 없이 결정을 위임하는 것이다.
**우리 판단과 그 산정 근거를 먼저 제시**하고 조정을 요청한다.

> ✗ 계측 대상 로트와 회차를 확정해 주십시오.
> ✓ 계측 가능 범위(안) — 대상 로트·회차와 각각의 산정 근거. 여건에 따라 조정 요청.

## 3. 정확성

### 3.1 상태 표기

추정을 실측처럼 쓰지 않는다. 세 단계를 **주장이 있는 자리에** 부기한다(범례에만 배치하지 않는다).

| 표기 | 의미 |
|---|---|
| 실측 | 실제로 측정된 값 |
| 구현됨 | 수단은 존재하나 해당 측정에는 미사용 |
| 미측정 | 아직 측정하지 않음 |

가운데 단계의 이름은 분야에 맞춘다 — 계측 문서라면 `레시피 보유`,
소프트웨어라면 `구현됨`이 읽힌다. 세 단계라는 구조는 바꾸지 않는다.

### 3.2 용어는 사업 문서와 맞춘다

같은 말이 사업 문서와 다른 시점을 지시하면 오해가 발생한다.
공정 기준 문서·고객 합의서의 용례를 먼저 확인하고 문서 전체에서 일관되게 쓴다.

> 예 — 합의서상 「양산」은 인증 통과 이후를 지시하는데 문서에서 파일럿 라인 작업을
> 「양산」이라 부르면 충돌한다. 파일럿 구간은 「양산 준비」 또는 「양산 검증」으로 적는다.

### 3.3 논란 가능 내용의 근거 확인

기한·의무·책임이 걸린 서술은 **어느 문서 몇 조에 있는지 확인**하고 인용한다.
확인되지 않거나 분쟁 소지가 있으면 문서에서 제외한다.

### 3.4 기준이 바뀌면 명시적으로 고지

이전에 공유한 수치와 산출 기준이 달라졌다면, 수치가 개선되었더라도
**기준 변경 사실을 별도로 명시한다.** 후속 비교에서 혼선을 막는다.

> 예 — 수율을 양산 조건 기준으로 재산출하였다면, 이전 공유분과 조건이 다르다는 사실을
> 수치 옆에 명시한다. 수치만 갱신하면 개선폭이 과장되어 전달된다.

## 6. 적용 절차

1. **초안은 내용 위주로** 쓴다. 문체 교정을 하며 쓰면 논지가 흐려진다.
2. **기계 치환** — 어미(§1.4)와 제목(§1.1)은 전역 치환으로 잡힌다.
   어미 치환은 인용문·코드 블록을 건너뛴다.
3. **판정 적용** — 치환표에 없는 표현은 원리로 판정한다.
   - §1.3 주어를 사람·물건으로 바꿔 자연스러우면 은유다
   - §1.4 문서 전체가 한 어체인지 확인한다
   - §1.8 그 동사에 목적어를 바꿔 끼워 의미역이 넓은지 확인한다
4. **§2 프레이밍**을 절 단위로 검토한다. 제목의 주어가 무엇인지 확인한다.
5. **§3 정확성** — 상태 표기, 용어 정합, 근거 확인.
6. **§4 체크리스트**를 돌린다. 편집을 여러 번 하였다면 매번 돌린다.

**치환표는 예시이지 목록이 아니다.** 표에 없다고 통과가 아니며, 3의 판정을 함께 적용한다.

**검사 범위는 문서 전체다.** 본문 산문만 확인하면 아래가 누락된다.

- [ ] **절 제목** — §1.1 명사구 여부. 서술형 제목이 가장 자주 남는다
- [ ] **표의 좌·우변** — 교정안(우변)도 §1.8을 통과해야 한다
- [ ] **도해 라벨 · 캡션 · 표 셀** — §1.4 어미가 여기에서 자주 어긋난다
- [ ] **본문 산문** — 규칙을 서술하는 문장 자신이 규칙을 위반하는 경우가 있다

치환 목록 전체는 `references/substitutions.md` 참조.

## 7. 판단이 필요한 지점

기계적으로 적용하면 안 되는 경우가 있다. 다음은 **사용자에게 확인**한다.

- **정정 고지** — 톤을 부드럽게 하더라도 사실 자체는 남겨야 하는 경우가 있다.
  이전 공유 수치의 정정, 기준 변경 고지가 그렇다.
- **한계 서술** — 임의 기준·미측정 항목을 지우면 수치가 검증된 것처럼 읽힌다.
  삭제 요청을 받아도 **한 줄로 이전하여 존치할지** 확인한다.
- **조직 내부 용어** — 레포·현장에 굳어진 말(`골든 웨이퍼`, `핫 로트`)은 임의로 바꾸지 않는다.
- **쉬운 말과 정밀한 말이 충돌할 때** — 외부 문서라도 의미역이 갈리는 자리에서는
  한자어를 유지하고 처음 나올 때 한 번 풀어 쓴다. 쉽게 바꾸다 계약 의미가 넓어지는 편이 더 위험하다.
- **삭제의 연쇄** — 한 항목을 지우면 다른 항목이 중복되거나 무의미해지는 경우가 있다.
  발견하면 알리고 함께 정리할지 묻는다.
